Two Settings defects: a silent Update button and a panel that leaks

Reported together, unrelated in cause. One is a missing distinction the API never carried; the other is a CSS track blowout this codebase has already met once and fixed.

Defect 1 — the yt-dlp Update button says nothing

Clicking Update flickers the button label and changes nothing else. When the installed build is already current, the version that comes back equals the one already on screen, so a working update is indistinguishable from a dead button.

The API cannot help. handleYTDLPUpdate returns {"version": …} only, and ytdlp.UpdateLatest re-downloads the latest release without ever reading the version it replaces — "already up to date" is not knowable at any layer.

Fix

Read the version before replacing it and report both. YTDLPVersioner already exposes Version alongside UpdateLatest, so no interface or wiring changes.

type ytdlpUpdateResponse struct {
    Version         string `json:"version"`
    PreviousVersion string `json:"previous_version"`
    Updated         bool   `json:"updated"`
}

Failing to read the previous version is deliberately not fatal: the binary may be missing entirely, which is exactly when an update is most wanted. That case reports no previous version and counts as an update.

Updated describes the version, not the download. The binary is reinstalled every time regardless, so updated:false means the version did not move — never that the fetch was skipped. The copy stays honest about that.

The note persists until the next click rather than fading, so the answer is still there when you look back at it. It renders through the same .retain-note every other note on the page uses, and rests visible — nothing is revealed on hover.

Defect 2 — the Download format cards push out through their panel

.presets used grid-template-columns: 1fr 1fr, which is minmax(auto, 1fr). That auto floor is each item's min-content width, and every card holds a white-space: nowrap format selector around 60 characters long. So each track grew to fit its own untruncated string, the text-overflow: ellipsis below it never engaged, and the grid overran .sect's padding and border.

This is the defect the library card grid already fixed — .grid uses repeat(3, minmax(0, 1fr)) and gridlayout.test.ts pins it. That test only scanned .grid, which is how .presets and .row2 went unguarded.

Fix

Two halves, both load-bearing: the minmax frees the track, the min-width frees the item sitting in it.

- grid-template-columns: 1fr 1fr;
+ grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);
+ .preset { min-width: 0 }
+ .row2 > .ctrl { min-width: 0 }   /* scoped: .ctrl is used all over Settings */

The single-column @media (max-width: 620px) overrides convert too. A lone bare 1fr is still minmax(auto, 1fr), so leaving them would fix the wide case and ship the narrow one.
