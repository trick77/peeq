Five tracks, no fixed order

The scoped follow-up to the architecture review. Five independent tracks covering the four substantive improvements plus every god class in the codebase — sized, sequenced only where they genuinely collide, and with the traps named up front rather than discovered during implementation.

Status, 2026-07-26. Nine PRs merged: Track A complete (#202 drifts, #196 Go enums, #198 TS guards, #204 the role slice that closed the last scrape gap) and Track E complete (#190). Track B is 3 of 8 — playback (#191), sharelink (#193), rag (#203) — leaving six concrete stores in Deps. Track D is 1 of 4 (#194). Track C has not started.

Two things this plan got wrong, recorded rather than quietly edited. The ytdlp → sponsorblock inversion — the review's finding 4, and its cheapest item — was dropped when eight findings were folded into five tracks; it is still unfixed. And the VTT timing bug in Track A1 was overstated as live data loss: yt-dlp emits HH:MM:SS.mmm, so the anchored Go regex never actually drops a peeq-produced caption file. It is spec-compliance hardening, not a production defect.

Two corrections to the earlier framing

Both came out of reading the code rather than reasoning about it, and both change what gets built.

Code-generating types.ts is off the table. The wire surface is 33 httpapi DTOs, plus 5 on-wire structs outside httpapi (activity.Event, activity.UpcomingItem, settings.Settings, auth.User, playback.State), plus ~15 ad-hoc map[string]string acks with no struct at all, plus two SSE payloads that are map[string]any literals in main.go, plus 10 more hand-mirrors living outside types.ts entirely. A generator covering half the surface leaves the drift class open while adding a build step, a prettier constraint and a coverage-exclusion change. Track A does the same job without it.
Interface extraction will not reduce httpapi's import count. Every candidate also uses package-level types, consts and functions — videos.ListOptions, settings.Patch, playback.State, rag.BuildFTSMatch. Both existing precedents, ActivityReader and SummaryLister, still reference activity.Page and summaryjobs.Job. Track B buys testability, not decoupling — and should be judged on that.

A2 · Name the unnamed enums in Go

Seven sets are bare literals whose only authority is a SQL CHECK. A guard cannot exist until a constant does. Add typed constants beside the four sets that already have them (videos/availability.go, activity/store.go, auth/model.go, channels/staleness.go): video status, summary status, download job state, summary job state, summary phase, cookie status, ledger state — then replace ~40 literal sites.

Trap. summarize/worker.go:379 has pipelineStages = {"summary","classify","embedding","keypoints"}. Those are log stage names, deliberately different words from the four wire phases. Do not merge them.

A3 · Drift guards

Reuse enumsync.test.ts as the mechanism, and copy its path resolution exactly — dirname(fileURLToPath(import.meta.url)) then resolve(). Its header explains why: Vite statically rewrites new URL("../x", import.meta.url) into an asset URL under jsdom, and fileURLToPath then throws. Keep its toBeGreaterThan(0) assertion too, so a failed regex parse fails loudly instead of passing vacuously.

Clean regex targets: the A2 constant blocks, videos/store.go sortClauses, share_handlers.go shareTTLs, activity/store.go kinds and outcomes, videos/availability.go Availabilities. Then turn the guarded sets into real TS unions instead of bare string.

A4 · Delete a parser instead of guarding it

The VTT pair is behavioral duplication — a guard can't cover it. The backend already parses cues (subtitles.Parsed.Cues) but serves raw .vtt bytes, so the UI parses a second time. Add GET /api/videos/{id}/cues and its share twin; ui/src/vtt.tsx then keeps only rendering and loses parseVtt, PAREN_SOUND_EVENTS, stripSoundEvents, ENTITIES, sameLines — the entire mirrored half.

Keep the raw .vtt endpoint: the Player offers a .vtt download. A4 supersedes A1's VTT row — but ship A1's regex fix anyway if A4 slips, because the data-loss bug shouldn't wait.

Track B · 8 PRs

B

httpapi testability via consumer-side interfaces

start with B1

You cannot test a handler without a real SQLite database. That is why httpapi carries 10,100 test lines against 4,012 production lines, why 31 raw db.Exec calls sit in one test file, and why playback_handlers_test.go:23 documents a drop-a-table trick to force store errors. Findings 2 and 5 from the review are one defect seen from two ends.

Precedent to copy exactly: DownloadsRunner, ActivityReader, SummaryLister — interface declared in the handler file that uses it, with the doc comment explaining why.

Start with B1. One file, the interface equals the entire store surface, five raw-SQL tests to convert. It proves the direction cheaply and is trivial to abandon.

Three things that will bite.
1 · videos.Store.Get returns (*Video, error) and signals not-found as (nil, nil). lookupVideo depends on that contract for its 404 — preserve it, don't "clean it up".
2 · Deps.Channels is blocked. channelmeta.Refresher.Channels is declared *channels.Store and server.go:259 constructs the Refresher from it. B8 requires widening that field too.
3 · rag.BuildFTSMatch is a package-level function passed as an argument — no interface can capture it, so B3 keeps the rag import regardless.

There is no shared newTestServer — there is openTestDB plus eleven per-area <x>TestDeps constructors each re-doing the same auth block. Each B-PR replaces its area's *sql.DB-returning variant with an error-returning fake. Do not attempt a big-bang test-helper rewrite; incrementality is what makes this track land.

Track C · 3 PRs

C

Extract channelsvc

half already exists

1065 lines encoding real policy: handle precedence, a load-bearing clear-then-subscribe ordering, a four-step delete cascade, scan gates duplicated from the scheduler, and a background goroutine launched from a GET.

Half the service already exists. internal/channelmeta was created precisely because two callers needed the same fetch-and-store step — Refresher.Resolve is shared by the refresh handler, the read-triggered resolve, and the weekly worker. The gap: handleChannelsPost inlines the image fetch, save and mark itself, because it resolves by URL (UCID not yet known) while Resolve resolves by known channel ID. The pending handlers are a different bounded context — leave them where they are, or give them their own service later. Do not fold them in.

Four traps.
1 · Handle precedence deliberately differs — Post lets the pasted URL win, Refresher lets the stored handle win. A naive merge silently changes behavior.
2 · handleChannelRefresh uses WithoutCancel(r.Context()) so a closed tab doesn't stamp resolve_ok=0. That's genuinely HTTP-shaped — it becomes an explicit ctx argument, not something the service invents.
3 · Store.DB() has ~60 test call sites in channels_handlers_test.go. A service that hides the store must still expose the DB, or all of them rewrite. Plan the tests inside the PR.
4 · Dormancy policy lives in two files — staleness.go:159 and the same bound inlined into List. And DormantChannels has no non-test caller; List's inline column superseded it. Resolve both here.

Callers that must not break: the scan scheduler uses 8 methods plus two exported constants, channelmeta uses 7, and download/worker.go already depends on a narrow ChannelCache interface — the precedent for how to depend on this. Crucially, the entire user-facing surface has no non-httpapi caller and is safely movable.

Track D · 4 PRs

D

Frontend god components

follow the views/channel/ precedent

The precedent is already in the repo: parent owns the shared resource and reload, children own their own local state, no barrel file (imports are by path), shared logic in a sibling .ts — views/channel/schedule.ts exists because two children had drifted on the same string.

The one constraint that decides whether this is cheap or expensive. Player.test.tsx is 1716 lines and renders <Player> whole, asserting through the DOM — it imports no internal helper. It survives a child-component split unchanged, exactly as Channel.test.tsx survived the ArchiveTab/NewTab split — provided the <video> element and its ref stay in Player. Five resume/version tests drive fireEvent on that element and assert on setResume args. Move it into a child and they all break.

D1 · Pure presentational children

MediaStats (already a separate in-file component), ContentsCard, SidebarPanels, the meta header. Zero shared state, zero behavior change, zero test change.

D2 · TranscriptCard, shared with the public share page

The big one. Player.tsx:1092-1222 and Share.tsx:400-508 are the same markup, the same CSS classes and the same four-way loading/error/empty/list branch, differing only in URL source. Also dedupes downloadTranscriptTxt (byte-equivalent in both) and the transcript fetch effect.

While here, dedupe the rest of the Player↔Share copies: the SponsorBlock auto-skip loop, the toast plus timer plus unmount cleanup, the subtitlesReadyFor iPadOS workaround including its copy-pasted 10-line comment, the chapters card and the highlights list. And move describe("parseVtt sound-event stripping") out of Player.test.tsx — it never tested Player.

Chromeless-import hazard to fix here. Share.tsx imports daysUntil from components/ShareControl.tsx, which imports createShare/stopShare from the ../api barrel. So the public share page's module graph already pulls in the authenticated share-management client and the whole API surface. Move daysUntil to a share-neutral module.

D3 · The three hooks

useStageToast (cleanest), useCaptions (shares subtitlesReadyFor with the loaded-metadata handler), usePlayback (resume/position, but it calls showToast and setVideo). Highest risk — do last, and only if D1/D2 felt right. The ⋮ action handlers stay in Player: every one mutates video optimistically and reads two refs.

D4 · App.tsx 806 → thinner

Keep the architecture. Pushing cross-device state to the backend and treating the server as the shared-state layer is correct — do not add Zustand, Redux or context. Two mechanical reductions instead:

  • Five per-view search strings are lifted only because they were lifted. Confirm none survives navigation deliberately, then move each into its view.
  • A ~40-line useResource<T>() hook returning {data, loading, error, reload} absorbs the loading-state bookkeeping — jobsLoaded, summariesLoaded, pendingCount: number | undefined — plus the three refresh callbacks. No dependency, no store.

That is 8–10 of the 21 hooks. The rest — SSE fan-in, auth, route — genuinely belong at the shell.

Collision rules

Order is otherwise free. Only these five constrain it.

RuleWhy
C before B8Both rewrite channels_handlers.go. Track C's extraction is the channels interface conversion — doing both means doing it twice.
A4 supersedes A1's VTT rowIf the cues endpoint lands, the regex fix is moot.
E before B6E moves videos.Store methods between files; B6 declares interfaces against those signatures. Trivial either way, but E-first avoids a rebase.

Do not stack. Master is protected, you merge by hand, and CI tests the PR merged with master — a stale stacked branch produces CI-only failures that pass locally. Independent branches off a fresh master sidestep it.

Verification

Per PR, before requesting review:

cd backend && go build ./... && go vet ./... && gofmt -l .   # CI gates on gofmt inline
cd backend && go test -race ./...
cd ui && npm run format:check && npm run build && npm test -- --run --coverage
make coverage                                                # floors: backend 75, ui 75

Four CI checks: backend, ui, extension, extension-e2e.

Patch coverage is diff-cover at 80%, and it will bite two tracks.
D1/D2 — a pure-mapping component split moves already-covered JSX into a new file where diff-cover sees it as new. Move the corresponding tests in the same PR.
A2 — a file of const declarations emits no executable lines. The backend path runs hack/strip-comment-lines.go first, which handles comments but not const blocks; assert_matched has a fallback for legitimately-uninstrumented diffs. If it still trips, [skip patch-coverage] in a commit message is the documented escape hatch — the 75% absolute floor still applies.
