Coverage gate

A statement-coverage floor enforced in CI, starting at today's measured numbers and ratcheting to a hard 80%.

For agentic workers: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this task-by-task.

Goal: fail any PR whose statement coverage drops below a committed floor, and make that floor climb toward 80%.

Architecture: one bash script computes coverage for either side and compares it to a key=value floors file committed in the repo. Backend coverage is recomputed from the Go coverprofile with awk so cmd/peeq can be excluded; UI coverage is read from vitest's json-summary. CI calls the same script a developer calls locally.

Stack: bash, awk, node (already required by the UI build), Go's built-in cover tooling, @vitest/coverage-v8.

Superseded in part. Tasks 1–4 below were implemented as written, against a statements metric with a ratcheting floor toward 80%. That was then replaced: the rule became a hard 75% floor on lines, and -coverpkg=./... was added. The reworked design is the spec, not this plan. Two things forced the change — Go exposes no line metric, so the backend number now comes from a Cobertura conversion; and that conversion also fixed a real bug, since with -coverpkg the raw profile repeats every block once per test binary and the awk here summed the duplicates, reporting 4.9% for a ~72% codebase. The CI wiring in Task 4 was reverted: the gate is red by design until coverage is backfilled.

Global constraints

  • Metric is statements only — never branches, functions or lines.
  • The floor caps at 80.0 and never rises above it.
  • cmd/peeq is the only backend exclusion.
  • A shortfall fails the job (non-zero exit), blocking merge.
  • No bot commits, ever. release.yaml fires on every push to master with no path filter — an automated floor bump would cut a spurious release and could loop.
  • Backend keeps -race; coverage uses -covermode=atomic to pair with it.
  • No new backend dependencies. The script uses only bash, awk and node.
  • Floor values are measured, never guessed — see the warning below.

Do not hardcode 72.2 / 68.1

Those were measured before this plan adds a coverage block to vite.config.ts, which changes the set of files vitest counts. Master has also moved since. Task 2 and Task 3 each measure first, then write the floor. If your measured number differs from the spec's, the measurement wins — record it and move on.

[ ]Step 1 — write the failing self-test

Fixture profiles are written inline by the test, so it depends on nothing in the repo. cmd/peeq lines are deliberately terrible (0 of 100 covered) to prove the exclusion works.

#!/usr/bin/env bash
# hack/coverage-gate.test.sh — self-test for coverage-gate.sh
set -uo pipefail
cd "$(dirname "${BASH_SOURCE[0]}")/.."

TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT
fail=0

check() { # check <label> <expected-exit> <actual-exit>
  if [ "$2" = "$3" ]; then
    echo "  ok   $1"
  else
    echo "  FAIL $1 (expected exit $2, got $3)"; fail=1
  fi
}

# 80 of 100 statements covered outside cmd/peeq -> 80.0%.
# cmd/peeq contributes 0 of 100 and must be ignored entirely.
cat > "$TMP/backend.out" <<'PROFILE'
mode: atomic
github.com/trick77/peeq/internal/auth/auth.go:1.1,2.2 80 1
github.com/trick77/peeq/internal/auth/auth.go:3.1,4.2 20 0
github.com/trick77/peeq/cmd/peeq/main.go:1.1,2.2 100 0
PROFILE

printf 'backend=79.0\nui=50.0\n' > "$TMP/floors-under"
printf 'backend=81.0\nui=50.0\n' > "$TMP/floors-over"

COVERAGE_FLOORS="$TMP/floors-under" COVERAGE_FILE="$TMP/backend.out" \
  ./hack/coverage-gate.sh backend >/dev/null 2>&1
check "passes when above floor" 0 $?

COVERAGE_FLOORS="$TMP/floors-over" COVERAGE_FILE="$TMP/backend.out" \
  ./hack/coverage-gate.sh backend >/dev/null 2>&1
check "fails when below floor" 1 $?

out=$(COVERAGE_FLOORS="$TMP/floors-under" COVERAGE_FILE="$TMP/backend.out" \
  ./hack/coverage-gate.sh backend 2>&1)
case "$out" in
  *80.0*) echo "  ok   excludes cmd/peeq (reports 80.0%)" ;;
  *)      echo "  FAIL excludes cmd/peeq — got: $out"; fail=1 ;;
esac

./hack/coverage-gate.sh bogus >/dev/null 2>&1
check "rejects unknown side" 2 $?

[ "$fail" = 0 ] && echo "coverage-gate: all checks passed"
exit "$fail"

[ ]Step 3 — write the gate
#!/usr/bin/env bash
# hack/coverage-gate.sh <backend|ui>
#
# Fails when statement coverage falls below the committed floor in
# hack/coverage-floors. The floor only ever rises, and stops at 80.
#
# Backend coverage is recomputed from the raw coverprofile rather than scraped
# from `go tool cover -func`: that prints a total but gives no way to exclude a
# package, and cmd/peeq (main() wiring) is deliberately not counted.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
FLOORS="${COVERAGE_FLOORS:-$ROOT/hack/coverage-floors}"
CAP=80.0
SIDE="${1:-}"

die() { echo "coverage-gate: $*" >&2; exit 2; }

case "$SIDE" in
  backend|ui) ;;
  *) die "usage: $0 <backend|ui>" ;;
esac

[ -f "$FLOORS" ] || die "floors file not found: $FLOORS"
FLOOR="$(awk -F= -v k="$SIDE" '$1==k {print $2; exit}' "$FLOORS")"
[ -n "$FLOOR" ] || die "no floor for '$SIDE' in $FLOORS"

if [ "$SIDE" = backend ]; then
  FILE="${COVERAGE_FILE:-$ROOT/coverage/backend.out}"
  [ -f "$FILE" ] || die "no coverprofile at $FILE — run the tests first"
  # Fields: <path>:<range> <numStatements> <executionCount>. Line 1 is "mode:".
  PCT="$(awk 'NR>1 && $1 !~ /\/cmd\/peeq\// { t += $2; if ($3 > 0) c += $2 }
              END { if (t == 0) { print "0.0"; exit } printf "%.1f", 100 * c / t }' "$FILE")"
else
  FILE="${COVERAGE_FILE:-$ROOT/coverage/ui/coverage-summary.json}"
  [ -f "$FILE" ] || die "no coverage summary at $FILE — run the UI tests first"
  PCT="$(node -e 'const s=require(process.argv[1]);
                  process.stdout.write(s.total.statements.pct.toFixed(1))' "$FILE")"
fi

# Compare with a 0.05 grace so float formatting alone can never fail a build.
if awk -v p="$PCT" -v f="$FLOOR" 'BEGIN { exit !(p < f - 0.05) }'; then
  echo "coverage-gate: $SIDE FAILED — ${PCT}% of statements, floor is ${FLOOR}%" >&2
  echo "  Add tests, or lower the floor in $FLOORS and say why in the commit." >&2
  exit 1
fi

echo "coverage-gate: $SIDE ok — ${PCT}% of statements (floor ${FLOOR}%)"

# Ratchet: suggest raising the floor, but never commit it automatically.
# release.yaml triggers on every push to master, so a bot commit here would
# cut a spurious release.
if awk -v p="$PCT" -v f="$FLOOR" -v cap="$CAP" \
       'BEGIN { exit !(p >= f + 0.5 && f < cap) }'; then
  NEW="$(awk -v p="$PCT" -v cap="$CAP" 'BEGIN { printf "%.1f", (p > cap ? cap : p) }')"
  echo "coverage-gate: floor can rise ${FLOOR} -> ${NEW}."
  echo "  Set '${SIDE}=${NEW}' in hack/coverage-floors in this PR."
fi

[ ]Step 1 — replace the backend test step

Coverage replaces the bare go test -race ./... rather than running alongside it — a second full test run would double CI time for no signal. Keep the surrounding go build and go vet steps and the existing CGO_ENABLED: "1" comment about the race detector needing cgo.

      - run: go test -race -covermode=atomic -coverprofile=../coverage/backend.out ./...
        env:
          CGO_ENABLED: "1"
      # The gate script resolves paths from the repo root, not backend/.
      - run: ./hack/coverage-gate.sh backend
        working-directory: .

The backend job sets working-directory: backend as a job default, so the coverprofile path is ../coverage/ and the gate step must override the directory back to the root. Add mkdir -p coverage before the test step if the run fails on a missing directory.
