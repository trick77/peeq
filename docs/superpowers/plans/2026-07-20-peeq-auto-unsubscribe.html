peeq · implementation plan · 2026-07-20

Auto-unsubscribe stale channels

Dead channels (deleted × 3 consecutive scans) unsubscribe themselves; dormant ones (no new video in 6 months) are only flagged. A health interlock stops a bad cookie from emptying the subscription list.

branch feat/auto-unsubscribe 5 tasks TDD spec mockup

For agentic workers: REQUIRED SUB-SKILL — use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Each task ends with an independently testable deliverable and a commit.

Goal, architecture, stack

Goal: peeq stops scanning channels that no longer exist, and surfaces channels that have gone quiet — without ever destroying archived media or acting on an untrustworthy signal.

Architecture: The decision rules live in channels.Store as plain data operations, unit-testable without running a scan. The scheduler only feeds them: increment on a deleted terminal error, reset on any clean scan. The HTTP layer exposes the review list and two actions; the UI renders the approved Option A layout.

Stack: Go 1.26 (CGO_ENABLED=0), SQLite via ncruces/go-sqlite3, append-only SQL migrations, React + TypeScript + Vitest.

Global constraints

  • Env prefix BACKEND_, never PEEQ_. This slice adds no new env var and no new config — thresholds are Go constants.
  • CGO_ENABLED=0; English comments; conventional commits.
  • Migrations are append-only. Create 0002_auto_unsubscribe.sql; never edit 0001_init.sql.
  • Tests use fakes only — never a real LLM, embeddings endpoint, real yt-dlp, or network.
  • Fakes must emit what the real thing emits.
  • Cookie invariant, 20 s throttle floor, kill-switch and SafeMediaPath untouched. Exactly one route bypasses OIDC (PUT /api/machine/cookie) — unchanged; every new route is behind requireAuth.
  • Unsubscribing must never delete media. Unsubscribe touches only the subscriptions row.
  • CI green: Backend (build + vet + go test -race), UI, Extension (test), Extension (browser).

AutoUnsubscribe must be atomic

It deletes the subscriptions row and inserts the auto_unsubscribes record. Do both in one transaction: a crash between them would leave a channel silently unsubscribed with no visible record — precisely the invisible-automation failure this feature exists to avoid.

-- 0002_auto_unsubscribe.sql — staleness tracking for subscriptions.

-- Consecutive scans that returned a terminal "deleted" for this channel.
-- ANY clean scan resets this to 0, so only a sustained run ever acts.
ALTER TABLE subscriptions ADD COLUMN dead_scan_count INTEGER NOT NULL DEFAULT 0;

-- When the user dismissed a dormancy flag. The flag re-arms only if a video
-- is discovered AFTER this instant and the channel then goes quiet again.
ALTER TABLE subscriptions ADD COLUMN dormant_dismissed_at TEXT;

-- The visible record of what peeq unsubscribed on its own. Outlives the
-- subscriptions row it replaces. The single-value CHECK is deliberate: a
-- future reason must widen it consciously, so the Go constant and the SQL
-- enum cannot drift apart silently.
CREATE TABLE auto_unsubscribes (
    channel_id TEXT PRIMARY KEY REFERENCES channels(id) ON DELETE CASCADE,
    reason     TEXT NOT NULL CHECK (reason IN ('deleted')),
    at         TEXT NOT NULL DEFAULT (datetime('now'))
);

Three boundaries that must each have their own test

A channel with no discovered videos at all must never be flagged — absent data is not evidence of dormancy, and a brand-new subscription would otherwise be flagged the moment it is created. Dismissal must suppress. A discovery after a dismissal must re-arm it.

cd backend && go test ./internal/channels/ -run Dormant -v
SELECT s.channel_id, c.name, MAX(cv.discovered_at) AS last_seen
FROM subscriptions s
JOIN channels c ON c.id = s.channel_id
LEFT JOIN channel_videos cv ON cv.channel_id = s.channel_id
GROUP BY s.channel_id
HAVING last_seen IS NOT NULL                       -- never flag on absent data
   AND last_seen < datetime(?, '-6 months')
   AND (s.dormant_dismissed_at IS NULL OR last_seen > s.dormant_dismissed_at)
ORDER BY last_seen

This task contains the single most important test in the slice

The interlock. If cookie_status is blocked/stale/ absent, or YouTube is paused, a channel at the threshold must not be unsubscribed, and the counter must not be incremented. // staleUnsubscribe applies the dead-channel rule. It is deliberately inert
// while YouTube access is unhealthy: a stale cookie can make EVERY channel
// fail at once, and acting on that would empty the subscription list. The
// counter is not even incremented, so an outage cannot accumulate toward
// the threshold.
func (s *Scheduler) staleUnsubscribe(ctx context.Context, channelID string, reason string) {
	if reason != channels.ReasonDeleted {
		return
	}
	if paused, _ := s.d.Settings.YoutubePaused(ctx); paused {
		return
	}
	switch s.d.Settings.CookieStatus(ctx) {
	case "blocked", "stale", "absent":
		return
	}
	n, err := s.d.Channels.RecordDeadScan(channelID)
	// ... on err: log and return.
	if n < channels.DeadScanThreshold {
		return
	}
	// ... AutoUnsubscribe(channelID, channels.ReasonDeleted, now); log at Info —
	// an automatic action must always leave a trace.
}

Call ResetDeadScan wherever a scan completes cleanly (alongside the existing MarkScanned call). Verify the exact success path before editing.

Definition of done

  • Backend 26+ packages -race green; UI green; extension unchanged and green.
  • A channel reporting deleted on 3 consecutive scans is unsubscribed, recorded, and its archived videos still exist.
  • The same channel is not unsubscribed while the cookie is unhealthy or YouTube is paused.
  • No non-deleted terminal reason ever increments the counter.
  • Dormant channels appear in the band; dismissal suppresses; a later discovery re-arms.
  • Re-subscribe restores the subscription and clears the record.
  • No new env var; every new route behind requireAuth; OIDC bypass still exactly one route.
