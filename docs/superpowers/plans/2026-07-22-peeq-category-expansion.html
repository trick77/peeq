Category enum expansion & full reclassification

The enum was fourteen knowledge/tech verticals with no lifestyle bucket at all, so a cycling channel had nowhere to go and landed in Entertainment. Eight categories are added, the classify prompt gains per-category hints, and every video is reset and re-classified by the worker's existing idle sweep.

status implemented enum 15 → 23 migration 0004 backfill full reset

Why the classifier was not the problem

The classify prompt deliberately forces a choice — ClassifiableCategories() withholds uncategorized from the model, and the system prompt says "always choose the closest match even when the fit is imperfect". That was the right call (an escape hatch just filled the bucket nobody browses), but it has a consequence: a missing category does not produce uncategorized, it produces a confidently wrong neighbour. GCN in Entertainment is the enum's fault, not the model's.

Hint is Go-only

videos.Category gains a third field, Hint, rendered into the classify prompt for the categories whose neighbours blur (a car review is automotive, not tech; a kitchen renovation is home, not engineering). It is not mirrored into ui/src/categories.ts and nothing in the UI shows it — enumsync.test.ts matches the field and drops it. The prompt now renders one category per line, because the hints carry commas of their own.

Backfill: migration 0004

-- backend/internal/store/migrations/0004_category_manual.sql
ALTER TABLE videos ADD COLUMN category_manual INTEGER NOT NULL DEFAULT 0;
UPDATE videos SET category = 'uncategorized';

Clearing the column is the backfill: the summarize worker's idle sweep (classifyOne → NextUnclassified) already picks up any downloaded video that is uncategorized and has a summary. No new machinery. SetCategory now also maintains the flag — one rule, both callers: a real category is the human speaking (Player pick → flag set), a reset to uncategorized is Re-summarize handing the video back to the classifier (flag cleared). SetCategoryIfUnset gained AND category_manual = 0.

Two things this knowingly costs

Pre-migration hand-picks are lost. Those rows carry no flag and are indistinguishable from classifier output, so the reset takes them too. Confirmed with the user; the flag protects picks made from here on.

The Library reads Uncategorized until the sweep drains. One LLM call per video (summary-only, cheap), and classifyOne runs only when the summary job queue is empty — while the TubeArchivist import is still producing summary jobs, classification is starved entirely. Count the rows before applying on the live host: 

sqlite3 /data/peeq.db "SELECT category, COUNT(*) FROM videos GROUP BY category ORDER BY 2 DESC;"
